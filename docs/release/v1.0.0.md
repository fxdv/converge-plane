# Converge v1.0.0

Converge is a self-hosted issue tracker with a built-in agent swarm: machine
members that work the board under a trust policy, escalate honestly to humans,
and leave a full disclosure trail on every handoff.

## What shipped (M0 → D4)

| Milestone | Scope |
|---|---|
| M0 | Go server (chi, stdlib only, zero runtime dependencies) + Postgres + pnpm workspace (`@converge/services`, `@converge/types`, `@converge/ui`) |
| M1 | Auth (magic-link sign-in/up, sessions), workspaces, teams, issues, workflows |
| M2 | Issue mutations, comments, realtime sync (sync outbox + SSE stream) |
| M3 | Converge identity: rebranded packages, new mark, all Tegon traces removed |
| M4 | Teams, labels, workflows, views, search, workspace preferences |
| M5 | Workspace administration: members, invites, suspension |
| M6 | Agent actors: machine workspace members, suspension, API tokens |
| D1 | Swarm runtime: per-agent workers, deterministic policy, escalation guard, the Human Review parking protocol |
| D2 | Swarm panel on the board: fleet roster, needs-human queue |
| D3 | LLM decision policy: self-hosted model fleet, per-agent GPU sharding, deterministic fallback, 24h token budget |
| D4 | The swarm plane: per-workspace fleet settings (topology + foreman), the dedicated Swarm page, rich "where things stand" handoff notes, the aligned needs-human chip |

Full feature, technical, and roadmap detail: `docs/spec/product-spec.tex`
(build: `make spec` — the PDF is a build artifact, never committed).

## The swarm, in one paragraph

A fleet of agent members (one LLM instance per agent, sharded across GPUs)
runs a decision loop per workspace. The policy layer is swappable: a
deterministic floor (state machine + guards) ships, and a self-hosted LLM
proposes decisions on top of it, falling back to the floor on any failure.
Agents advance state, post human-visible comments, and hand work off. When an
agent cannot finish, it pauses the card, posts a fenced handoff comment with a
task-level "where things stand" note, and parks the card in the Human Review
column — no agent works cards there, and the resume gesture is a human move
back into the workflow. Topology is a fleet setting: **foreman** (one
dispatcher) or **flat** (peers may hand to peers), steered from the Swarm
page, taking effect on the swarm's next decision.

## Known limitations (v1.0)

- **Agents have no external tools.** They advance state and write comments;
  work that needs real execution (git, CI, deploys, tags) is escalated to a
  human or done by the foreman outside the board.
- **LLM failure degrades, it does not stop.** Endpoint or validation failure
  falls back to the deterministic policy; the fallback is logged and visible
  as generic step comments. The swarm keeps moving without a brain.
- **The Human Review fence is a hard boundary.** Even a card a human grants
  the swarm cannot be carried *through* Human Review by the swarm — a card in
  that column is never queued, so completion across the fence requires the
  human's own move.
- **Token budget is a rolling 24h guard per agent** — a resumed card can be
  re-paused by the quiet guard while the pattern is still in-window.
- **Ops are manual**: the release itself (tag, notes, runbook) is cut by a
  human. This runbook is the first artifact in that direction.

## Upgrade

Migrations are forward-only and applied at boot (v1.0 ships 0001–0015, the
last being the `swarm_settings` table). Redeploy the server binary, then the
web build; the client is server-version tolerant for the sync protocol.
